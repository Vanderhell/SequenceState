# SequenceState – Implementation & Research Prompt Pack

## Základné pravidlá pre všetky prompty

Pracuješ na experimentálnom projekte **SequenceState**.

Cieľ projektu:

> Overiť, či malý fixed-size deterministický stav dokáže zachovať prakticky využiteľnú informáciu o dlhej usporiadanej sekvencii lepšie než jednoduché baseline mechanizmy pri porovnateľnej alebo nižšej pamäťovej a výpočtovej réžii.

Nejde o vytvorenie LLM.

Nejde o vytvorenie kryptografického hash algoritmu.

Nejde o dokazovanie vopred zvolenej hypotézy.

Výsledok projektu môže byť:

```text
KEEP
MODIFY
REJECT
```

Negatívny výsledok je plnohodnotný výsledok.

# PROMPT 2 — Implementuj viac matematických kandidátov

Pokračuj priamo nad aktuálnym stavom repository.

Cieľ tejto fázy nie je nájsť pekný algoritmus.

Cieľom je vytvoriť niekoľko **zásadne odlišných matematických kandidátov** a objektívne ich porovnať.

## Implementuj minimálne 6 candidate families

Každý kandidát musí mať samostatné ID a samostatnú implementáciu.

### Candidate A — rotate/xor/add

Použi kombináciu:

```text
rotate
xor
add/sub
symbol-derived constants
lane permutation
```

Musí byť order-sensitive.

---

### Candidate B — multiply/add modular transform

Rodina približne:

```text
S' = A(S, x) * S + B(x) mod 2^32
```

Nepoužívaj jednu spoločnú lane transformáciu pre všetky lane.

Musí existovať cross-lane mixing.

---

### Candidate C — reversible lane permutation

Použi bijektívne alebo lokálne invertibilné operácie:

```text
rotate
xor
odd multiplication
lane permutation
ARX
```

Cieľ:

* silná order sensitivity,
* dobrá distribúcia,
* možnosť neskoršej lokálnej reverzibility.

---

### Candidate D — structured geometric/invariant transform

Skús transformáciu inšpirovanú pôvodnou geometrickou myšlienkou.

Nemusí ísť o skutočný kruh.

Použi integerový stav a definuj explicitný invariant alebo približne zachovávanú veličinu.

Príklady:

```text
Hamming weight class
pairwise lane energy
quadratic modular form
balanced lane sum
```

Invariant musí byť merateľný.

Ak invariant spôsobuje degeneráciu, zaznamenaj to.

---

### Candidate E — permutation-driven state

Symbol nech vyberá alebo generuje deterministickú permutáciu/mixing transformáciu.

Sekvencia:

```text
A B C
```

musí byť kompozíciou transformácií:

```text
TC(TB(TA(S0)))
```

Nie iba hash(symbol).

---

### Candidate F — composability-oriented candidate

Navrhni kandidáta od začiatku s cieľom budúceho:

```text
combine(state(A), state(B))
≈
state(A || B)
```

Môže potrebovať metadata ako:

```text
length
power/transform summary
```

ale celková veľkosť musí zostať fixed-size.

Ak je potrebné rozšíriť stav o dĺžku:

```c
typedef struct
{
    uint32_t lane[8];
    uint64_t length;
} ...
```

je to povolené iba pre tento experiment.

# PROMPT 3 — Implementuj tvrdé baselines

Než začneš hodnotiť kandidátov, implementuj férové baseline mechanizmy.

Minimálne:


```text

+

+

```

## Dôležité

```text

```

```text

```

# PROMPT 6 — Combine experiment

Túto fázu vykonaj iba po dokončení predchádzajúcich testov.

Cieľ:

```text
state(A || B)
```

vs.

```text
combine(state(A), state(B))
```

## Najskôr analyticky

Pre každého kandidáta urč:

```text
exactly composable
approximately composable
not composable
```

Nesnaž sa silou-mocou vytvoriť `combine()` tam, kde algebra kandidáta túto vlastnosť nemá.

## Pre vhodných kandidátov implementuj

```c
ss_state_t ss_combine(
    const ss_state_t *left,
    const ss_state_t *right);
```

Ak je potrebná dĺžka segmentu, explicitne ju zahrň.

## Testy

Rozdeľ rovnakú sekvenciu:

```text
A|B
AB|C
A|BCD
random split
many equal chunks
unequal chunks
```

Porovnaj:

```text
streamed state
combined state
```

Ak exact:

```text
bit-identical PASS/FAIL
```

Ak approximate:

meraj definovanú metriku.

## Associativity

Testuj:

```text
combine(combine(A,B),C)
```

proti:

```text
combine(A,combine(B,C))
```

na minimálne státisícoch deterministicky generovaných prípadov.

Ak asociativita nie je exact, musí byť explicitne označená ako approximate.
