# SequenceState

## Research & Implementation Specification v0.1

## 1. Cieľ projektu

SequenceState je experimentálny deterministický systém pre reprezentáciu dlhej usporiadanej sekvencie pomocou malého stavového vektora s pevnou veľkosťou.

Základná otázka projektu:

> Dá sa sekvencia veľkého počtu vstupov priebežne skladať do malého fixného stavu tak, aby výsledný stav zachoval prakticky využiteľnú informáciu o poradí, vzťahoch a štruktúre sekvencie?

Projekt nemá vytvárať nový LLM.

Projekt nemá nahrádzať Transformer, Mambu ani neurónové siete.

Prvým cieľom je vytvoriť a experimentálne overiť novú alebo užitočnú matematickú primitívu pre sekvenčný stav.

---

# 2. Základná predstava

Máme vstupnú sekvenciu:

```text
x1, x2, x3, x4, ... xn
```

Namiesto uloženia celej sekvencie vytvárame stav:

```text
S0
 ↓ x1
S1
 ↓ x2
S2
 ↓ x3
S3
 ...
 ↓ xn
Sn
```

Každý nový stav vznikne:

```text
S(n+1) = update(Sn, x)
```

Veľkosť `S` je počas celého spracovania konštantná.

Napríklad:

```text
128 bit
256 bit
512 bit
1024 bit
```

bez ohľadu na to, či sekvencia obsahovala:

```text
10
1000
1 000 000
```

prvkov.

---

# 3. Základný princíp

Vstup nesmie byť iba pripočítaný k stavu.

Každý vstup predstavuje matematickú transformáciu:

```text
x → T(x)
```

a:

```text
S' = T(x)(S)
```

Sekvencia:

```text
A B C D
```

je teda:

```text
S = TD(TC(TB(TA(S0))))
```

Cieľom výskumu je nájsť transformáciu alebo rodinu transformácií, ktorá zachováva čo najviac užitočných vlastností sekvencie.

---

# 4. Kľúčová hypotéza

Existuje fixed-size stav `S` a lacná transformácia:

```c
update(S, x)
```

taká, že výsledný stav zachová viac prakticky využiteľnej štruktúry sekvencie než primitívne akumulátory typu:

```text
XOR
SUM
hash
mean
```

pri porovnateľnej alebo menšej pamäťovej a výpočtovej réžii.

---

# 5. Druhá, silnejšia hypotéza

Existuje operácia:

```c
combine(A, B)
```

taká, že:

```text
state(sequenceA + sequenceB)
```

je rovnaký alebo dostatočne ekvivalentný:

```text
combine(
    state(sequenceA),
    state(sequenceB)
)
```

Formálne chceme skúmať vlastnosť:

```text
S(A || B) = combine(S(A), S(B))
```

kde `||` znamená konkatenáciu sekvencií.

Toto je jedna z najdôležitejších požadovaných vlastností projektu.

---

# 6. Asociativita

Ideálne:

```text
combine(combine(A,B),C)
=
combine(A,combine(B,C))
```

Teda:

```text
(A ⊗ B) ⊗ C = A ⊗ (B ⊗ C)
```

Asociativita umožňuje sekvenciu spracovať:

```text
A B C D E F G H
```

ako:

```text
AB
CD
EF
GH
```

potom:

```text
ABCD
EFGH
```

a nakoniec:

```text
ABCDEFGH
```

To umožňuje:

* paralelizáciu,
* stromovú redukciu,
* cacheovanie podsekvencií,
* inkrementálne spracovanie,
* distribuované spracovanie.

Asociativita nie je povinná pre prvý prototyp `update()`, ale je zásadným cieľom ďalších fáz.

---

# 7. Poradie musí byť zachované

Systém nesmie byť komutatívny.

Musí platiť:

```text
A ⊗ B != B ⊗ A
```

aspoň s veľmi vysokou pravdepodobnosťou alebo podľa presne definovaných algebraických vlastností.

Napríklad:

```text
A B C
```

musí byť odlíšiteľné od:

```text
C B A
```

a:

```text
A B
```

od:

```text
B A
```

Poradie je základnou vlastnosťou sekvenčných dát.

---

# 8. Fixed-size stav

Prvá implementácia musí podporovať minimálne:

```text
64 bit
128 bit
256 bit
512 bit
```

Preferovaný hlavný experimentálny variant:

```text
256 bit
```

Príklad:

```c
typedef struct
{
    uint32_t lane[8];
} ss_state256_t;
```

Stav nesmie obsahovať:

* pointer na externé dáta,
* dynamickú pamäť,
* rastúci buffer,
* zoznam predchádzajúcich vstupov.

# 13. Update primitíva

Minimálne API:

```c
void ss256_update(
    ss_state256_t *state,
    uint32_t symbol);
```

Požiadavky:

```text
O(1) pre jeden symbol
fixed RAM
bez branch-heavy logiky, ak je možné
bez lookup tabuliek závislých od veľkosti dát
```

Kandidátne stavebné operácie:

```text
ADD
SUB
XOR
rotate
shift
multiply
permutation
lane permutation
bit mixing
modular arithmetic
```

Použitie modulo `2^32` alebo `2^64` je povolené, ak je explicitne súčasťou definície algoritmu.

---

# 14. Norm-preserving experiment

Pôvodná geometrická intuícia projektu vychádza z konštantnej vzdialenosti bodov na kružnici.

Túto myšlienku treba experimentálne preniesť do stavového priestoru.

Nemusí ísť doslova o euklidovskú normu.

Treba skúmať transformácie, ktoré zachovávajú invariant:

```text
I(S') = I(S)
```

Možnosti:

```text
Hamming weight
modular norm
energy
quadratic form
lane-wise invariant
permutation class
```

Experimentálna floating-point referencia môže skúmať aj:

```text
||S|| = constant
```

ale produkčný integer core nesmie byť na floating pointe závislý.

# 16. Nejde o kryptografický hash

Projekt nesmie automaticky smerovať k:

```text
SHA-256(sequence)
```

Kryptografický hash výborne rozlišuje vstupy, ale zámerne ničí väčšinu štrukturálnej podobnosti.

Chceme, aby podľa potreby platilo napríklad:

```text
ABCDEF
```

bolo reprezentáciou bližšie:

```text
ABCDEG
```

než:

```text
ZXCVBN
```

ak je taká vlastnosť pre daný experiment užitočná.

Toto musí byť merané, nie predpokladané.

# 21. Hash baseline

Hash musí byť použitý hlavne ako kontrola:

```text

```

```text

```

To samo o sebe nie je cieľom projektu.

# 22. Combine

Druhá fáza musí zaviesť:

```c
ss_state256_t ss256_combine(
    const ss_state256_t *left,
    const ss_state256_t *right);
```

Požadovaný experiment:

```text
A = sequence[0..499]
B = sequence[500..999]

SA = state(A)
SB = state(B)

SC = combine(SA, SB)

SD = state(A || B)
```

Merať:

```text
SC == SD
```

alebo mieru ich ekvivalencie.

Ideálny výsledok:

```text
SC == SD bit-exact
```

Nie je to však povinné pre prvé experimentálne návrhy.

# 24. Random access nie je cieľom v0.1

V0.1 nemusí umožniť:

```text
daj mi presný symbol číslo 785231
```

Fixed-size lossy stav to vo všeobecnosti nedokáže.

Prvým cieľom sú agregované a štrukturálne vlastnosti.

---

# 25. Reverzibilita

Úplná reverzibilita:

```text
state → pôvodná sekvencia
```

nie je požiadavkou.

Pre ľubovoľne dlhú sekvenciu a fixed-size stav by bola bezstratová reverzibilita informačne nemožná.

Môžeme však skúmať:

```text
lokálnu reverzibilitu
invertible update
symbol removal
prefix removal
state difference
```

napríklad:

```c
ss256_remove_last(state, symbol);
```

ak to algebra umožní.

---

# 32. Avalanche nie je automaticky výhoda

Kryptografický hash chce:

```text
1-bit change
→
úplne iný output
```

SequenceState nemusí.

Treba experimentovať medzi:

```text

```

```text

```

Príliš malý môže vytvárať kolízie a degeneráciu.

# 33. Kandidátne algebraické rodiny

Experimenty môžu skúšať:

### A. Modular transforms

```text
S' = A*S + B(x) mod 2^w
```

### B. Rotate/XOR/Add

```text
S' = ROT(S, f(x)) XOR g(x)
```

### C. Lane permutation

```text
permute lanes
mix symbol
rotate
```

### D. Matrix-like integer transform

Malé implicitné matice bez všeobecného matrix multiply.

### E. Reversible permutations

Každý symbol vyberá bijektívnu transformáciu.

### F. Norm/invariant-preserving transforms

Transformácie udržiavajú zvolenú invariantnú veličinu.

Žiadna rodina nie je vopred preferovaný víťaz.

# 49. Hlavné meradlo úspechu

Projekt je úspešný, ak nájdeme aspoň jednu primitívu, pre ktorú platí:

> Malý deterministický fixed-size stav zachováva prakticky využiteľnú štruktúru dlhej sekvencie s lepším pomerom pamäte, výpočtu alebo composability než jednoduché existujúce baseline riešenie.

Nemusí ísť o univerzálnu reprezentáciu.

Úzka oblasť použitia je akceptovateľná.

# 50. Výskumná filozofia

Nezačíname tvrdením:

> „Vytvoríme nový AI systém.“

Začíname otázkou:

> „Existuje matematická primitíva, ktorá dokáže robiť túto jednu vec lepšie?“

Ak odpoveď bude nie:

```text
projekt splnil účel
```

Ak odpoveď bude áno:

```text
primitíva
    ↓
sequence engine
    ↓
ML experiments
    ↓
možná nová architektúra
```

Architektúra má vzniknúť z výsledkov experimentov.

Nie naopak.
